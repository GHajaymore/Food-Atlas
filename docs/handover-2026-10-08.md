# Handover — WikiFoodia, 8 October 2026

Written for whoever picks this up next. Everything here is current as of this date and
verified on the live site rather than inferred from the code.

## What this is

A free atlas of traditional food: 17,358 records built from Wikipedia, Wikidata, Wikimedia
Commons, Wikibooks and open regional registers, every one showing the evidence behind it.
No advertising, nothing tracked, no money collected anywhere.

- **Code**: `C:\Users\morea\Documents\Apps\Global best food app\global-taste`
- **Remote**: `github.com/GHajaymore/Food-Atlas`
- **Live**: https://wikifoodia.ajailabs.app (Cloudflare Pages + Pages Functions + D1)
- **Owner**: Ajay, AjAi Labs. He reads the pages, not the diffs — fixes he can see matter.

## How to run it

```
npm test                 # 721 tests, ~6 minutes
npm run build            # static export + prerender + build gate, ~4 minutes
npm run check:pages      # reads every kind of screen in a headless browser, ~2 minutes
npx.cmd wrangler pages deploy      # deploys dist/ to production
```

`npm run deploy` runs build, check:pages and the deploy in that order and stops at the
first failure. `check:pages` (added 8 October) serves `dist/` locally with the API stubbed,
opens fifteen kinds of screen in English at two widths, German at phone width, and the
home, a record and the proposals list in every other language, plus the filtered browse
states — 78 page loads, with sample confirmations and a sample proposal stubbed in so those
screens actually render — and
fails on what a reader would notice: copy keys printed as words, unfilled placeholders,
sentences run together, the same long sentence twice, an authenticity claim without the
badge, a bare-brand tab title, an internal value on a filter chip, a count missing its
thousands separator, an image without alt text, a control with no accessible name, sideways
scroll, script errors. Each rule is proven against
the exact string that once shipped in `__tests__/page-faults.test.ts`. It found a repeated
sentence in German on its first run.

`npx.cmd`, never `npx` — PowerShell's execution policy blocks the `.ps1` shim on this
machine, and the fix is the `.cmd`, not changing the policy. Never pass `--project-name`;
it is in `wrangler.toml`. Verify on the deployment URL the deploy prints, not on the custom
domain — the edge serves the old copy for a while.

For the Functions and a local D1 (reads and writes without touching production):
`preview_start` with the `wikifoodia-functions` entry, which runs
`wrangler pages dev dist --port 8788 --local`. Apply migrations locally first with
`npx.cmd wrangler d1 migrations apply wikifoodia --local`.

## The rules this project is built on

Break these and the project stops being what it is.

1. **Never show a number the reader cannot check.** No invented percentages, no cooking
   times, no ratings. If a figure is displayed, something computes it from the data.
2. **A claim must match what is on the screen beside it.** The faults that matter here are
   almost all of this shape: a heading that contradicts a badge, a ceiling that contradicts
   a gauge, a sitemap that contradicts robots.txt.
3. **Translations are hand-written, all twelve, or not made.** A machine translation beside
   a corrected English line is the same untruth in another language. The privacy page is
   English-only by design and says so.
4. **Nothing that costs money without asking Ajay first.** The only billable surface is
   Workers AI translation, which runs on a free daily allowance and stops.
5. **A control that goes nowhere is worse than no control.** If a thing cannot work yet,
   do not offer it.
6. **Ajay types his own secrets.** `IDENTITY_SECRET`, `ADMIN_TOKEN`. Never generate, ask
   for, or store them.

## Traps that have each cost an hour

- A build script calling `buildCatalogue` gets records whose `steps` and `prepSummary` are
  empty. Use `builtCatalogue()` from `scripts/lib/built-catalogue.mjs`. Both failures were
  silent — a smaller count, no error.
- On a record, ask `hasProse()` / `methodLength()`, never `prepSummary.trim()`.
- **Never delete a row from `cuisines.json` or `cookbook.json`** — ids are positions, so a
  deletion renumbers every later record. Exclude in `src/data/exclusions.ts`.
- Mapping a region label to a place can create a new violation: Tibetan → Tibet made
  "China › Tibet", one country inside another. The invariant test catches it; drop rather
  than translate in that case.
- Editing files from Bash: quoted heredocs are safe, `node -e` eats backticks and `${}`,
  and multi-line `String.replace` anchors fail on files git has rewritten to CRLF. Splice
  by line index.
- **Read the suite count, not just "passed".** On 8 October `npm test` printed "561
  passed" and exited 1: one whole suite had failed to load, and its 155 tests simply did
  not run. Piping through `tail` hid the exit code. Check the "Test Suites:" line, and
  that the total is ~716.
- Icons are imported per icon through `src/components/phosphorIcons.js` (with a `.d.ts`
  beside it), never from the `phosphor-react-native` root, which ships all 3,024. Jest
  maps those per-icon paths to the package's compiled CommonJS build (`package.json` →
  `jest.moduleNameMapper`), because it does not compile TypeScript inside node_modules.
- This session's guard refuses production database reads and writes. Migrations are Ajay's
  to run; write them so the code behaves before they do.

## Data repairs on 8 October

- **French recipes had lost their ingredient names.** French Wikibooks writes each
  ingredient through a template (`400 g de {{i|poireau|poireaux}}`) and the original import
  deleted every template, so 1,024 lines on 436 records read "400 g de", "100 g d'", "sel,".
  `scripts/repair-fr-cookbook.mjs` re-read the exact revisions each row recorded and
  rendered the templates the way the page does — 921 rows changed, 1,024 broken lines down
  to 5 (none French). It refuses any row where the repair would change, not just add to,
  what was there; Pan bagnat is the one it left for a person. Scores and badges identical.
- **Card text ended mid-word on 2,339 cards** ("…sugar, and s"): `cardBlurb` in build.ts now
  ends at a sentence, or at a whole word with an ellipsis.
- **9 October — the same template loss in the other four books, and in methods.** Spanish
  lost its oven settings and times ("precalentado a .", `{{temperatura|170}}`), Portuguese its
  `{{w|…}}`-linked ingredients ("1 lata de ;"), French its `{{ustensile|…}}` utensils in
  methods ("Faire des stries avec une."). `scripts/repair-wikibooks-templates.mjs` has each
  wiki expand every distinct template call (twice, under two titles, so `{{SUBPAGENAME}}`
  cannot leak a stand-in title), substitutes, re-reads with the import's own extractors, and
  **mends line by line**: a stored line is swapped only for a fresh one that keeps every
  word and number of it in order and adds at most twelve. Re-taking whole lists was tried
  first and brought back reference URLs earlier passes had removed. 553 lines on 265
  recipes; scores and badges identical.
- **9 October — one country's region printed inside another.** "Sarapatel — Goa,
  Portugal", "Weisswurst — Bavaria, Poland", "Hodge-Podge — Scotland, China".
  `ingest-geonames.mjs` had reported these for weeks ("Reported, never moved") and nobody read
  the report. `scripts/fix-cross-border-regions.mjs` is a reviewed table, each row read
  against its article: drop the region where the home is shared or disputed (always, when
  `originClaims` exists), correct the place only where the article's lead names it. 39
  records. "Sichuan Food (restaurant)" turned out to be an Amsterdam restaurant and is now
  in `exclusions.ts` (17,358 → 17,357 records; no id moved). The rest of that report —
  "Belgium › Limburg", "France › Réunion" — is GeoNames filing things differently, not faults.
- **9 October — 44 dishes the build had been silently dropping.** Buuz, Kepta duona,
  Kibbeh bil siniyeh, Mussels marinière and forty more. Their origin claims came from
  Wikidata, the source link was built from a Wikipedia URL they do not have, the
  "every claim is sourced" invariant failed, and the build drops a failing record without a
  word. Now the claim links the Wikidata item it was read from, `buildCatalogue` returns
  `droppedByInvariants`, and `plumbing.test.ts` requires it to be empty — **if that test
  fails, read the names; fix the record or the rule, not the test.** Found only because a
  place fix made Pastel de nata vanish the same way. Records 17,357 → 17,400; countries
  160 → 161 (Eritrea, via Kategna; Palestine had been counted twice, 161 → 160, earlier
  that night). `verify-prose-split.mjs` now matches by id and names what vanished — but it
  runs the *same* build code on both sides, so it cannot see a drop a code change causes.
- **9 October — more wrong places.** Cities of another country (Kottu "India ›
  Batticaloa", Hunan dumplings "China › Montreal"), and region names the GeoNames pass
  matched to a *town* of that name (Jiangnan → a town in Chongqing, Ontario → California).
  All in `fix-cross-border-regions.mjs`'s reviewed table; rows set `placeByHand`, which
  `ingest-geonames.mjs` now skips. A repeated level ("Lisbon › Lisbon") is cleared from
  the place itself, not just the breadcrumb — trimming only the breadcrumb is what made
  Pastel de nata break the breadcrumb-matches-place invariant.
- **9 October — 23 records that were not dishes** (a book, streets, a bar, brands, a
  template page, street-food overviews) added to `exclusions.ts`, each with its article's
  words; found by asking every name whether it reads like a dish. 26 recipes no longer
  print "User:Name/" in their name (stripped *after* the cookbook filter, since cookbook ids
  are positions in what it keeps — checked id by id). Records 17,400 → 17,376.
- **9 October — the Portuguese cookbook is mostly Brazilian.** Every recipe from it was
  filed under Portugal by the ingest's book default; 146 of 243 are written in Brazilian
  Portuguese (xícaras, creme de leite, suco, fubá, polvilho; mineiro, caipira) and now sit
  under Brazil, each row's `countryBy` naming the words that moved it
  (`scripts/fix-pt-cookbook-country.mjs`). A recipe with any European marker, or none,
  keeps Portugal. The same question is open for the Spanish cookbook (Spain vs Latin
  America — it already contains Ajiaco, Arroz con gandules, Bandeja paisa) and has not
  been measured.
- **9 October — the site's own sentences in every language.** Origin-claim lines, source
  notes, diet notes, published-recipe disclaimers and the cookbook card sentence were
  English on all twelve versions; now catalogue keys with hand translations (added to
  `docs/translation-review.md`, 46 strings). The privacy page stays English on purpose.
- Whole-catalogue audits found these, not the page check: run one before assuming a fault is
  rare. The ones that came back clean — photo credits, wiki markup in text, duplicate names,
  ingredient junk beyond 21 lines — are worth re-running after any new import.

## A decision taken on 8 October that Ajay may want to reverse

**The Diet and Meal filters are hidden.** Measured: diet is recorded for 6 of 17,358 records
and meal occasion for the same 6 — the hand-curated ones. Choosing Vegan returned two
dishes, and a reader reasonably took the atlas to hold two vegan dishes. The filters are not
deleted: `src/domain/classification.ts` offers them again automatically once one record in
twenty is classified, and a filter already set stays visible so it can be cleared. The record
page still says "Not classified" on each record. If the filters should stay visible anyway,
the change is that one threshold.

## A decision found on 9 October and left for Ajay

**32 records are filed under a country that none of their own origin claims name.** The
clearest: Strudel under Iran (claims Austria, Hungary), Nasi goreng under China (Indonesia,
Malaysia), Dracula Piller under the United States (Denmark, Sweden), Ärter med fläsk under
the United States (Sweden, Finland, Denmark, Norway), Fried bread under the United States
(Bohemia, Moravia), Tsoureki and Çiğ köfte under Iran. They came from cuisine categories:
a dish listed under "Iranian cuisine" was filed as Iranian. Seven also have a twin record
under one of their claimed countries (Tsoureki → Greece, Çiğ köfte → Turkey, Couscous →
Algeria, Marraqueta → Chile, Churrasco → Brazil, Pelau → Dominica, Ayran → Iran).

Not changed, because every fix picks something the project's rules refuse to pick: refiling
under the first claim names a winner, and excluding a twin removes a local record (couscous
in Lebanon is moghrabieh, and that may be a real fact). Several are fine as they are —
Vindaloo under India, Ropa vieja under Spain (the Canary Islands), Sata andagi under Japan.

**Recommendation:** exclude the seven that have a twin under a claimed country (they are
the same dish under a wrong flag, and the twin already carries it), and refile the no-twin
cases only where the article's lead names one home in plain words, as was done for Nasi
kandar. The list is reproducible: records whose `loc.country` is not among
`canonicalCountry(claim.place)` for their `originClaims`.

## The habit that found almost everything

**Read the rendered page in order, as a reader meets it.** Every significant fault in this
run was invisible in the diff and obvious on the screen: a form that could not submit, a
heading contradicting the badge two inches above it, the same thirty words printed three
times, a gauge marked twenty points above anything the catalogue can reach. The tests were
green through all of it.

Measure before trimming, too. "This page feels wordy" became tractable the moment it was
1,104 words of which 570 were prose and most of that the dish's own method.

   If it is still in Testing, strangers cannot sign in, so no confirmation can ever count
   toward a badge. Publishing with only the `openid` scope should not need Google's review.
1. **Nothing until Ajay's three steps.** Launch is one string away and everything else is

2. **Watch the first real confirmation.** The feature is live and untested by a stranger.
   The first one will show whether the form asks the right things.
3. **The first-load payload.** The JavaScript is fixed: on 8 October a source map showed
   one icon library was 77% of the bundle (all 3,024 icons shipped for the seven used), and
   importing each icon on its own took the download from 1,441 KB to 445 KB and what a
   phone parses from 7.4 MB to 1.7 MB, measured over the network. The data then went from
   2,142 KB to 2,047 KB on the wire by no longer shipping 12,178 article links the titles
   beside them rebuild exactly (`src/domain/articleUrl.ts`). Measured field by field, what
   is left is not waste: card text (433 KB, all on records with an account — the cards
   print it), local names (305 KB) and cookbook ingredients (371 KB), both of which search
   reads at first paint. Deferring those trades a second of incomplete search and needs the
   per-record search cache rebuilt when they land — a decision, not a cleanup. What remains
   is ~2 MB of JSON, because every reader downloads the whole catalogue. Splitting the data by
   country or shelf is a real piece of work, not a build-step change; worth doing before a
   campaign that brings phone readers in volume.
4. **Native-speaker review of `docs/translation-review.md`** — the 24 sentences that matter
   most, in all twelve languages beside the English, generated from the catalogues. Not one
   string in the twelve has been read by a fluent speaker.
5. **A rail for records waiting to be confirmed was tried and reverted** on 8 October: it
   is exactly the `cookable` set today — 4,479 records both ways, measured — so it would
   have been one pool under two headings on a page already criticised for crowding. Revisit
   when confirmations exist and the two sets differ.
