## The architecture change that matters

**The catalogue is fetched, not bundled.** `src/data/catalogue.ts` used to `import`
four JSON files; Metro inlines a static import, so 16,000 records of prose became
24 MB of JavaScript and 20–30 seconds of parsing before first paint.

- `src/data/build.ts` — the transformation. All the rules. This is what the tests exercise.
- `src/data/catalogue.ts` — live bindings plus `loadCatalogue()`.
- `public/data/*.json` — what is served. Regenerate with `node scripts/compact-data.mjs`
  then copy `src/data/*.min.json` over `public/data/*.json`.
- `app/_layout.tsx` gates every route on the load, so the seven screens still read
  `catalogue` as a plain array.

**Native is not finished.** A device has no neighbouring `public/` folder.
`EXPO_PUBLIC_DATA_URL` supplies the origin there; web needs nothing.

## The two habits that found almost every bug

**1. Dry-run a rule before applying it.** Every deletion rule was run with `--dry`
first and the output read. This caught: `brand` prefix-matching "(Brandade de
Morue)" and "(brandy)"; "Culture of…" nearly deleting the UNESCO borscht record; an
"X of Y" rule about to remove 282 real provinces (Province of Chieti, Autonomous
Republic of Crimea).

**2. Read the app, not the data.** Three faults this session were invisible in JSON
where every field was individually true:
- The Italian cookbook told Italy its own cookbook was foreign to it.
- The place picker listed China and People's Republic of China as two countries.
- A register record printed "Nothing documents how this is made" above 899
  characters of its own production method.

## The recurring bug class — now covered by a test

Five times a script wrote something correct and the app ignored it. `sourceLanguage`
hard-coded to `'en'` in two mappings; ingredients read only from `evidence`;
`atRiskEvidence` re-derived from the recipe instead of the history; `originClaims`
written as strings into a field typed for sourced claims.

`__tests__/plumbing.test.ts` traces each field from the source row to the record
built from it. **Its first version could not fail** — it asked whether *any* record
showed a field, so deleting the at-risk plumbing left it green. It traces per record
now; reintroducing either bug turns it red, which was verified by doing exactly that.

| Multilingual Wikibooks cookbooks | **3,537 recipes with ordered steps** (fr 1,127 · es 836 · de 682 · it 642 · pt 250) |

**Dead ends, recorded so nobody repeats them:**
- **EU DOP/IGP register** — I said it was "a single download". It is not. eAmbrosia
  and GIview are HTML applications with no JSON; the only machine-readable EU data is
  map geometry of production areas.
- **Sicily's PAT file** — server refuses connections outright, not a timeout.
- **Social media photographs** — no free tier, and a credit line is not a licence.
  The lawful free route is the contributor publishing to Wikimedia Commons, which is
  what the contribute flow now asks for.
- **Matching a recipe to a Wikipedia article of the same name.** Measured first: 18%
  of photoless recipes have an article of exactly that title carrying a lead image.
  Then checked what it returned — 3 of the first 6 were wrong. "Arisa" (Malaysian
  blended chicken) matched an Italian singer photographed at Sanremo; "Arambasici"
  (Croatian) matched a Turkish dish; "Arjoli" (Maltese) followed a redirect to French
  aioli. An exact title match is not evidence of the same subject, and a redirect
  actively destroys it — MediaWiki says two names are one subject, not that two
  dishes are one dish. Abandoned; the six photographs were reverted and the script
  deleted rather than left as a trap.

  The mistake was in the probe, not the code: it measured *availability* and not
  *accuracy*. It answered "is there a picture" when the question was "is it the right
  picture". Any future source should be sampled for correctness before it is built.

- **~4,100 Italian PAT products** have no article in any language. One in eight has
  one anywhere. No amount of encyclopaedia scraping reaches them.

## Wikimedia, practically

One rate limit across every Wikimedia API, per IP. **Read `Retry-After`** — it says
four seconds. Guessing an escalating backoff made a four-second pause look like a
permanent outage and cost an hour of misdiagnosis plus six lost batches. Run one pass
at a time.

Two encoding traps, both real: Wikimedia appends UTF-8 tracking parameters to image
URLs (`Name.jpg?utm_source=…`), and MediaWiki returns titles with spaces where URLs
use underscores. Either one silently loses most of a run.

## What is left

**Needs a decision, not code:** translation is inert. `EXPO_PUBLIC_TRANSLATION_ENDPOINT`
is unset, so 5,108 non-English accounts can be identified but not read by someone who
does not speak the language. It needs a backend route holding an API key and a monthly
cap — the only part of this project that costs money.

**Free and available:**
- 3,657 recipes still have no photograph.
- `enrich-infobox` has rows it has not walked.
- Slow Food's Ark of Taste (~6,000 endangered foods) remains the best at-risk source
  and needs a partnership, not a scraper.
