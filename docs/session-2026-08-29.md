## The privacy page

Google will not let the OAuth app out of testing mode without a privacy policy, which is
why the consent screen still shows a bare domain instead of "WikiFoodia". So `/privacy`
exists — written to be true rather than to satisfy the form, because the front page
claims "nothing tracked" in four places and a policy that quietly contradicted that would
make the claim worse rather than better.

Ajay's objection to the first draft was the right one: **length is itself a claim.** Nine
sections implies nine things worth worrying about, on a site that holds no email address
and no name. Six now.

The section that earns its place is *Other people's servers*. Wikimedia and YouTube see a
reader's IP because the browser fetches images from them, and Cloudflare sees every
request. "Nothing tracked" without saying that is the kind of true-sounding
half-statement this project refuses everywhere else.

**English only, and the page says so in its own lede.** This is the one screen where a
guessed translation is worse than none — elsewhere a stiff sentence costs nothing, here a
wrong one is a false statement to a reader about their own data. Only the "Privacy" nav
label is translated; Italian and Dutch borrow the English word, which
`__tests__/domain.test.ts` now records in its same-word allowlist.

Operator is AjAi Labs, contact `contact@ajailabs.app` — checked for MX records first, and
`ajailabs.com` has none.

## The donation button pointed at a placeholder

Production was serving a Contribute button opening `https://ko-fi.com/example`, under a
footnote claiming it went to Open Collective.

No `.env` file exists in this repository or anywhere above it, and no such variable was
in the environment. **Metro had cached the inlined value** from some earlier build — the
exact trap `docs/deploy.md` documents for `EXPO_PUBLIC_*`, found from the other end this
time.

`npm run build` now passes `--clear`. Builds get slower; the alternative is silently
shipping whatever a previous build happened to inline.

With the value gone there is no destination, so the "Not open for donations yet" card
went too — it asked for nothing while promising a future ask, on a project that does not
collect money and is not waiting to. The wiring is untouched: `EXPO_PUBLIC_DONATE_URL`
brings the button back.

Afterwards, every other `EXPO_PUBLIC_*` was checked for the same silent loss.
`EXPO_PUBLIC_TRANSLATION_ENDPOINT` was the one that could have broken and it falls back
to `/api/translate`; confirmed live. Nothing else was relying on a cached value.

## Roles

Sign-in and administration were two systems that had never met. Signing in stored a
salted hash so that three confirmations meant three people; authority was `ADMIN_TOKEN`,
a shared string, unrelated to who you were.

**Three tiers.** `user` is everybody and is the *absence of a row*. `admin` is the
console. `owner` is one account: everything admin has, plus appointments.

**Who may create a role.** Whoever can set `ADMIN_TOKEN` claims the owner seat on a
database that has none — and only for the account making the request, so the token proves
the authority and the session cookie says who is claiming it. After that the token can no
longer appoint anybody and is break-glass only, because losing a Google account should
not be an unrecoverable outage while an appointment ought to appear in `granted_by` as
the act of a person.

Enforced rather than trusted: nobody leaves `user` by their own hand, the owner cannot be
removed, only the owner writes to the roster. "Exactly one owner" is a partial unique
index, because two owners is the one state the model cannot be reasoned about from.

**Ordinary readers still get no row anywhere.** That is what let the privacy page keep
nearly the sentence it had — it became "the only accounts this database stores are the
handful who run the site", changed in the same commit as the migration rather than after.

`/admin` has a lock now. It deliberately did not before and that reasoning was sound for
what it then was; then it grew analytics, which are not public. The gate is not the
security boundary — every write is checked server-side against the session's role — it
just makes the refusal happen once, in a sentence.

`__tests__/roles.test.ts` is checked by the **Functions** TypeScript project, not the
app's. It names `D1Database` and `PagesFunction`, which exist in one type world and not
the other; `functions/tsconfig.json` explains why the two are kept apart.

## A claim that had gone false

The front page said *"One thing does cost money, and it is switched off until it can be
paid for."* Workers AI went live on 27 August. False in English and in all twelve
translations, on a project whose whole claim is that it does not state things it cannot
stand behind.

Restated: translation runs on a free daily allowance and stops when it is used up rather
than billing anybody — which is what `functions/api/translate.ts` actually does.

**All twelve were restated in the same pass.** A stale translation is worse than a missing
one: the key still counts as translated, so coverage reports a language as done while it
states last month's fact. `restate.mjs` exists for that; `insert-copy.mjs` only ever
added keys that did not exist.

Two smaller ones alongside: `administrationNote` said the console "Needs a token", untrue
from the moment the roles commit landed; and `donationFootnote` names Open Collective
while the button goes wherever `EXPO_PUBLIC_DONATE_URL` points, so it now appears only
when the destination really is one.
